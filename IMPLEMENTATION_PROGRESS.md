## Архитектурные решения

- **Матч как композиция движков.** `worker/duel5-core.ts` запускает существующие движки (`rooms-core`, `reaction-core`, `memory-core`, `race-core`, `riddle-core`) как этапы. Каждый движок получил необязательное число раундов (`create(seed, rounds)`), по умолчанию прежнее значение, поэтому одиночные игры не изменились.
- **Один seed на этап, одинаковый для обоих.** Условия равны; seed выводится из seed матча и номера этапа.
- **Сообщения помечены этапом.** Каждое сообщение получает `stage` и `sid`; ход игрока с другим номером этапа игнорируется (устаревший ход не засчитывается в другом этапе).
- **Очередь — один Durable Object.** Нет нескольких пулов по рейтингу. Тик только пока кто-то ждёт (нет опроса БД). Игрок в матче заблокирован до конца матча (`/release` от комнаты) или на 2 минуты как предохранитель.
- **Результат сохраняется один раз.** Запись матча `INSERT … ON CONFLICT DO NOTHING`; рейтинг и награды только при первой записи.
- **Рейтинг считает сервер.** Клиент не присылает результат; только ходы.
- **Журнал валюты.** Каждое изменение — строка с уникальным `ref`. Дубликат падает по `UNIQUE` и откатывает весь батч, поэтому награда не начисляется дважды; покупка не уводит баланс в минус (`CHECK` и условный `UPDATE`).
- **День по Baku (UTC+4, без перехода на летнее время).** Лимиты наград сбрасываются в полночь по Баку.
- **Маршруты.** `/api/mm/ws` (очередь), `/api/matches/training|friend`, `/api/ratings/me|top`, `/api/economy/me`, `/api/matches/mine`. Новые маршруты подключены до подроутеров с `use("*", auth)`: иначе они получили бы 401 (найдено в e2e-проверке).

## Найденные и исправленные проблемы

1. Маршрут очереди отвечал 401: подроутеры с `use("*", auth)` действуют на все маршруты, подключённые после них. Перенёс `duel5Routes` выше.
2. `credit()` начислял дважды при повторе: условие «запись существует» истинно и при повторе. Переписал на уникальный `ref` внутри батча.
3. Шаблон «Повторить» был виден при поиске: класс `.btn` перебивал `hidden`. Добавил `[hidden] { display: none !important }` в `duel5.css`.
4. Статус этапа перетирался внутренним видом этапа: теперь перед ним название дисциплины.
5. Матч без второго игрока не освобождал игроков из блокировки. Теперь освобождает.

## Известные ограничения и риски

1. **Комнаты живут в памяти Durable Object.** При деплое или выгрузке объекта текущий матч и очередь теряются; клиент показывает «соединение потеряно» и кнопку повтора. Это ограничение существующей схемы (1 на 1 тоже так работает). Исправление: сохранять снимок комнаты в хранилище объекта.
2. **Рейтинг: чтение и запись без сравнения версий.** Два матча одного игрока, завершившиеся одновременно, теоретически могут перезаписать друг друга. Вероятность низкая; исправление — условное обновление по версии.
3. **Длительность матча.** С одним молчащим игроком матч длился 151 с (таймауты памяти, внимания и логики). Цель 90–150 с достижима, когда оба играют; подбор времён — в `config/match.ts` и движках.
4. **Загадки на азербайджанском в русском интерфейсе** (существующий контент).
5. **Ссылка «дружеский матч»** открывается любому, у кого есть код. Матч без рейтинга.
6. **Подозрительные матчи** помечаются (`matches.flag = 'repeat'`), но экрана проверки нет.
7. **Не проверено в браузере:** ход в логике (мой клик пришёлся после 15-секундного окна раунда; логика проверена юнит-тестом), Safari, Android Chrome, PWA, планшет.
8. **Iowa Gambling Task (`src/experiments/iowa-gambling.ts`).** Проверен: это классическая симуляция с выбором из четырёх колод; ставок нет, реальных денег нет, Qızıl и рейтинг не затрагиваются. Формулировки связаны с деньгами: комментарий в файле говорит, что каждая карта «gives money», в азербайджанском тексте вопрос звучит «Hansı uzun müddətdə qazandırır?» (какая колода приносит доход в долгосрочной перспективе). По ТЗ стоит перевести на нейтральные «очки» до публичного запуска. Не сделано в этой сессии, каталог не менялся. Другие эксперименты на азартную механику не проверялись.
9. **Незакоммиченные изменения пользователя** (`tsconfig.json`, `vite.config.ts` с плагином AdSense, `functions/`, `public/ads.txt`, два документа в `docs/`) не тронуты и не закоммичены. Сборка уже включает плагин AdSense из `vite.config.ts`.
